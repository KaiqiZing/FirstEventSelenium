1.3 各层职责与设计目的

① 配置层 config/ —— 双配置源分离

文件作用设计目的
settings.yaml环境地址、超时、浏览器参数、下载目录、截图开关运行参数集中一处；env.active 切换环境
settings.pyConfig 单例配置中心，点路径读取全局只加载一次；缺键返回 default；格式错误抛 ConfigError 带配置键/文件证据
*Element.ini ×637 场景元素定位，key=by>value定位与代码物理分离：前端改样式只动 INI；by 缺省 xpath 降低书写成本

② 定位层 base/find_element.py —— 场景码注册器

  • 场景码前缀（I/W/M/C/X/E）→ 分组 INI 映射表 GROUP_INI，Section 名即场景码本身。
  • 解析 by>value 为 Selenium (By, value) 元组，支持 8 种定位方式。
  • 双级缓存：INI 句柄缓存 + 定位器解析缓存，反复定位不重复读盘解析。
  • 与 WebDriver 完全解耦，可独立单测。

③ 基础层 common/ —— 等待体系 + 异常体系

webdriver_wait_common：所有元素操作唯一入口。显式等待三档（visible / presence / clickable），超时读取配置；click_params 原生点击失败自动 JS 兜底；等待超时当场截图并包装为 ElementNotFoundError（带定位器+截图路径）——取证发生在离现场最近的时刻。

exceptions：FrameworkError 基类定义 evidence() 协议，子类只供证据、__str__ 自动拼装；format_exception_chain() 展开异常链，硬性约定异常链恒为 2 层（技术根因→领域异常）；find_in_chain() 沿链捞取证据属性。

④ 操作层 handle/ —— 场景操作流

  • base_scenario_handle.py：基类传入场景码，loc(key) 一行完成「INI 读取→定位解析」，收敛 click/fill/js_fill/结果区断言。js_fill 用原生 value setter + 派发 input/change 事件，解决 Vue v-model 受控组件 send_keys 不同步。
  • action_support.py：跨场景平台动作库（窗口句柄、嵌套 iframe、Shadow DOM 穿透、原生 alert、hover/拖拽、上传、富文本、滚动容器）。
  • *_handles.py ×6：每个场景一个 Handle 类，只描述「怎么操作这个页面」，不含流程编排。

⑤ 业务层 business/ —— 业务组合 + 异常打标

  • *_business.py ×6：Handle 原子操作按业务步骤组合，每步包 biz_step(...)（等价 allure step）。
  • business_context.py：异常流打标层。从调用栈自动推断场景码（run_e01_xxx → E01），三分类处理：FrameworkError 裸重抛不套链；AssertionError 包装为 BusinessError 并 raise from 挂「场景码+步骤+入参」；其余异常原样透传。
  • 复杂场景用 NamedTuple 返回结构化结果（如 I18RecapResult），「取数」与「断言」分离。

⑥ 用例层 case/ —— 用例 + fixture + 收敛取证

  • test_*.py ×6（37 用例）：open_scenario(driver, "/i/01") 直达路由，断言统一落在页面底部「操作结果」日志区。
  • service_preflight（session 级）：探活前端 + GET /api/health，快速失败；端口 5173/5174 自动探测回退。
  • driver fixture：--browser 覆盖配置，创建/回收驱动。
  • pytest_runtest_makereport hook：失败收敛层——不看异常类型不做分支，统一收拢 ①异常链全文 ②元素级截图（沿链捞取）③用例级现场截图进 allure；取证失败只降级 warning，绝不掩盖原始失败。

1.4 架构设计的三条主线

1. 配置与代码分离

元素定位（INI）、运行参数（YAML）全部外置，代码零硬编码定位串。

2. 断言源可信分级

页面可见内容 ≠ 可信断言源。稳定断言点依次为：「操作结果」日志区 → 服务端 API → SQLite 库 → CDP 网络层，页面 DOM 仅作辅助。

3. 可降级设计

allure、CDP 取证、performance 日志、JS 点击——增强能力失效时一律降级而非失败，保证任何浏览器/环境下核心断言依然成立。

第三部分：面试要点与实战问题

3.1 架构设计类（必问）

Q1：框架分几层？为什么这么分？
六层+横切：case → business → handle → base(定位) + common(等待)，util/config/log 横切。核心动机是变化隔离：前端改样式只动 INI，业务改流程只动 business，Selenium API 变化只动 common/handle，用例层只关心「打开哪个场景、断言什么关键字」。单向依赖保证任何一层可独立替换（如 network_recorder 从 CDP 换 BiDi，用例零改动）。
Q2：元素定位怎么管理？为什么用 INI 而不是 PO 类属性/JSON/YAML？
场景码注册器：场景码（I01）→ 分组 INI 同名 Section → key=by>value 解析为 (By, value)，双级缓存。选 INI 因为：一 key 一行可读性最好、无嵌套、configparser 标准库零依赖、与参考工程语义一致便于团队迁移。本质是把 PageObject 的「定位器仓库」从代码挪到配置，改动免改代码。
Q3：PO 模式在你这里怎么体现？
三层拆分：handle = 经典 PageObject（元素级操作），business = 业务流程对象（步骤编排+打标），case = 纯断言。比单层 PO 多出的 business 层解决「多用例复用同一段业务流程」的重复代码问题，也是 allure 步骤报告与异常打标的挂载点。
Q4：等待机制怎么设计？隐式等待为什么设为 0？
全部显式等待（WebDriverWait + EC 三档）。implicit_wait: 0 因为隐式与显式混用会造成等待时间不可预期叠加（Selenium 官方反模式）。非元素类条件（日志关键字、导出完成、写库就绪）用轮询封装（wait_result_contains / wait_db_equals），杜绝固定 sleep。
Q5：失败怎么定位？
三级取证：① 元素级——等待超时当场截图挂进 ElementNotFoundError；② 业务级——biz_step 把 AssertionError 包装为带场景码/步骤/入参的 BusinessError 并 raise from 挂链；③ 用例级——pytest hook 统一收敛异常链+链上截图+现场截图进 allure。约定异常链恒为 2 层，防止层层翻译埋掉根因。

3.2 Selenium 高频技术点

Q6：StaleElementReferenceException 怎么处理？I-03
根因：SPA 整表重建后旧元素引用失效。解法：不缓存元素对象，每次操作重新定位；确实持有元素的，捕获后重新定位重试。框架层面「定位器缓存、元素不缓存」是关键设计。
Q7：元素不可交互/点击被拦截怎么破？I-01/I-02
先等 element_to_be_clickable 而非仅 presence；遮罩场景等遮罩消失后再操作；scrollIntoView 滚到可视区；最后手段 JS 点击兜底（click_params 内置自动降级）。JS 点击绕过真实用户事件，兜底而非首选。
Q8：iframe / Shadow DOM 怎么处理？I-04/I-05
iframe：switch_to.frame 逐层穿透，完事 switch_to.default_content() 回主文档（双层必须逐层进逐层出）。Shadow DOM：Selenium 4 的 element.shadow_root 取 ShadowRoot 再 find_element，CSS 选择器无法穿透 shadow boundary。
Q9：Vue/React 受控输入框 send_keys 不生效？I-16/C-01
根因：框架监听 input/change 事件同步状态，clear+send_keys 在受控组件上可能残留旧值或不触发绑定。解法 js_fill：用原生 value setter 写值再手动 dispatchEvent(new Event('input',{bubbles:true}))。
Q10：多窗口怎么切换？M-01~M-04
操作前记录 window_handles 快照，等句柄数增加后切新句柄，完事切回。OAuth 小窗等「自动回传并关闭」：轮询句柄数回落再断言主窗口。非用户手势 window.open 会被拦截（M-04），保留默认弹窗策略复现并断言计数。
Q11：文件下载/上传怎么验证？I-10/W-03
下载：Chromium 用 prefs download.default_directory、Firefox 用 browser.download.dir + neverAsk.saveToDisk 静默落指定目录，断言产物存在。上传：直接对 <input type=file> send_keys(绝对路径)，绕过系统文件选择器。
Q12：原生 alert 与日期控件？I-11/C-01
driver.switch_to.alert 的 accept/dismiss/send_keys。原生 date/datetime-local 控件不走逐字 send_keys（各浏览器差异大），统一 js_fill 写 value + 派发事件。

3.3 数据与断言类（本项目特色）

Q13：金额断言为什么不能用 float？
浮点求和有尾差。本项目纪律：页面文本先 parse_amount 清洗（剥 ¥/千分位/括号负数/文案前缀）成 Decimal，一分钱容差比较（tolerance=0.005）；库侧单位是「分」，先 cents_to_yuan 统一单位。NULL（未清算）与 0 元语义不同，None 全程保留不参与求和。
Q14：页面数字和数据库核对怎么做才不脆弱？I-18
两原则：① 不写死任何期望值——条数/页数/期望金额全部从库动态推导（ceil 互推校验），样本按「角色」挑选；② 业务闭环驱动——「调整金额→重算汇总→页面变化量==调整增量 且 页面==库求和」，模拟真实业务链路。写库约 0.6s 延迟，必须轮询等待而非立即读。
Q15：加密场景为什么不能断言密文？E-01~E-04
OAEP/AES-GCM 都有随机填充/随机 IV，同一明文每次密文不同——密文相等断言必败。正确姿势：断言语义等价物——服务端解密结果的 SHA-256 摘要（脚本独立复算三方互校）；「同明文两次密文不同」反证随机性。页面 DOM 是前端自证不可信，真实报文用 CDP 抓网络栈取证。解密成功 ≠ 验签通过（E-04 时间戳过期 2001 与签名篡改 2002 分开断言）。
Q16：断言点为什么统一在「操作结果」日志区？
业务失败码 HTTP 仍 200，requests 层无感；失败提示走 ElMessage 会自动消失，时机不可控。只有底部日志区累积、稳定、可轮询。推广：UI 断言要选「稳定、累积、语义化」的锚点，不用 toast 这类瞬态元素。

3.4 工程化类

Q17：多浏览器怎么支持？
工厂+策略分支：create_driver 按类型分发五个创建函数；360/QQ 等国产浏览器别名归一 chromium，ChromeDriver + binary_path 指可执行文件（驱动主版本需匹配其内核，建议显式 driver_path）；Safari 仅 macOS 需 safaridriver --enable；沙箱参数仅 Linux 注入。--browser 覆盖 YAML，同一套用例形成浏览器执行矩阵。
Q18：能力降级怎么做？举三例。
① allure 未安装 → allure_compat 降级为日志，用例照常跑；② CDP 仅 Chromium → Firefox/Safari 下 NetworkRecorder.start() 返回 False，跳过网络层断言改接口层兜底；③ performance 日志缓冲有副作用 → UIEVENT_DISABLE_PERF_LOG=1 一键关闭。原则：增强能力永远不作为唯一断言源。
Q19：稳定性治理还做了什么？
会话级预检快速失败（避免 37 用例挨个超时）；端口 5173/5174 自动探测回退；W-05 不稳定接口重试到成功；截图命名清洗+时间戳；日志按天滚动 30 天；取证代码自身 try 兜底不掩盖原始失败。
Q20：框架怎么迁移到别的项目？
换 settings.yaml + 重写 6 个 INI + 按场景写 handle/business/case，框架层零改动。换技术栈（Playwright/BiDi）只需替换 webdriver_wait_common 与 network_recorder 的后端实现。

3.6 红线与职业判断（加分项）

不绕过被测系统安全机制：验证码用后端万能码不接 OCR；webdriver 特征检测只断言不注入反检测参数；弹窗拦截保留默认策略复现。自动化是验证手段，不是对抗手段。
缺陷归属判断：X-04 稳定失败时，通过「直连后端 vs 经前端代理均 500、同模块 GET 正常」交叉取证，定位为被测后端旧进程问题而非脚本问题——用证据说话，不替被测系统兜底，也不让脚本背锅。
测试数据自洁：I-18 用例开头结尾都调 reset 重建落库，可反复执行、无顺序依赖、无脏数据。
